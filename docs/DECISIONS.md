# Décisions et questions ouvertes

Statuts : 🔴 bloquant, ouvert · 🟡 proposition par défaut en attente de confirmation · ✅ décidé.

## Questions du CDC §9

| #   | Question                                                           | Statut | Bloque                      | Proposition / réponse                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------ | ------ | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Q1  | Types d'AG prioritaires (sociétés, copropriétés, associations)     | ✅     | T3 (presets), démos         | **Réponse (2026-10-01) : sociétés, puis associations, puis copropriétés.** Presets du Lot 1 : sociétés (SA, SARL, SAS statutaire) et associations ; copropriété ensuite                                            |
| Q2  | Taille maximale visée d'une AG                                     | 🔴     | T17, choix du plan Supabase | Supabase Pro limite par défaut les connexions Realtime simultanées (~500). 2 000 votants imposent un add-on                                                                                                        |
| Q3  | Terminaux : smartphones personnels, tablettes prêtées, ou les deux | ✅     | T8, T9                      | **Réponse (2026-10-02) : les deux.** Un code de vote par personne (QR + code saisissable), associé à un appareil ; une tablette prêtée se réassocie à la personne suivante (l'association précédente est révoquée) |
| Q4  | Valeur juridique de la signature à l'écran                         | ✅     | T9                          | **Réponse (2026-10-02) : la signature manuscrite à l'écran suffit** (image PNG + horodatage, tracée dans l'audit), sans prestataire qualifié                                                                       |
| Q5  | Modèle de vote secret (§7.3)                                       | 🟡     | T10                         | Modèle §7.3 : vote lié au membre en base, jamais exposé, résultats agrégés                                                                                                                                         |
| Q6  | Qui opère le jour J (régie MobilActif ou client autonome)          | 🔴     | T12                         | —                                                                                                                                                                                                                  |
| Q7  | Validation des presets par un juriste                              | 🟡     | mise en production          | `rule_presets.validated_by_lawyer`                                                                                                                                                                                 |

## Arbitrages techniques (pris en cours de lot)

| Date       | Sujet                          | Décision                                                                                                                                                                                                                                                                                                                                                                     |
| ---------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-10-01 | Périmètre des chaînes d'audit  | Une chaîne par `chain_id = coalesce(assembly_id, org_id)` : les événements d'administration (invitations, rôles) sont chaînés au niveau de l'organisation, ceux de séance au niveau de l'assemblée.                                                                                                                                                                          |
| 2026-10-01 | Emplacement des politiques RLS | Chaque migration active la RLS et pose ses politiques sur les tables qu'elle crée, au lieu d'une migration RLS unique : une table n'existe jamais sans protection.                                                                                                                                                                                                           |
| 2026-10-01 | Privilèges par défaut          | Les privilèges implicites de Supabase (ALL pour anon/authenticated/service_role, EXECUTE pour PUBLIC) sont retirés. Chaque migration accorde explicitement les `SELECT` et `EXECUTE` nécessaires. `service_role` ne peut pas non plus écrire dans les tables.                                                                                                                |
| 2026-10-01 | Création des organisations     | Réservée au super-admin MobilActif (les organisations sont les clients). Le premier super-admin est créé en SQL (cf. README).                                                                                                                                                                                                                                                |
| 2026-10-01 | Invitations (avant le Lot 2)   | Le lien d'invitation est affiché à l'administrateur, qui le transmet lui-même. L'envoi d'e-mails transactionnels arrive avec les convocations (Lot 2). L'invitation n'est acceptée que par un compte dont l'e-mail correspond.                                                                                                                                               |
| 2026-10-01 | Composants UI                  | Le registre shadcn n'est pas joignable depuis l'environnement de développement : les primitives (`components/ui`) sont écrites à la main au format shadcn. `components.json` est présent pour `shadcn add` quand le réseau le permet.                                                                                                                                        |
| 2026-10-01 | Historique des résolutions     | Une version immuable par création, modification ou suppression (et pas seulement après convocation), avec auteur, statut de l'AG et motif. Le motif est obligatoire dès que l'AG n'est plus en brouillon. L'historique survit à la suppression de la résolution.                                                                                                             |
| 2026-10-01 | Texte des résolutions          | Document Tiptap (JSON) au schéma restreint : gras, italique, intertitres, listes, citations ; ni liens ni images. Le HTML est produit côté serveur par le même schéma ; un document hors schéma n'est pas rendu (repli sur « texte non affichable »).                                                                                                                        |
| 2026-10-01 | Pièces jointes                 | PDF de 20 Mo maximum dans Supabase Storage (bucket privé `attachments`), déposés directement par le navigateur sous contrôle des politiques RLS, puis enregistrés par RPC (taille lue côté serveur). Un fichier référencé ne peut pas être supprimé de Storage. Téléchargement par lien signé valable 60 s.                                                                  |
| 2026-10-01 | Avis du conseil (B7)           | Préparé au niveau de chaque résolution (`board_recommendation` : pour / contre), proposé quand les pouvoirs en blanc suivent l'avis du conseil. Son application au vote est en attente de la confirmation de B7 (T10).                                                                                                                                                       |
| 2026-10-01 | Présence calculée              | `member_presence` n'est jamais modifié directement : chaque mouvement modifie des faits (personnes, pouvoirs) puis `refresh_presence` recalcule les membres touchés. Statuts : présent (porté en propre), représenté (pouvoir dont le mandataire est présent), parti (compté puis sorti), attendu.                                                                           |
| 2026-10-01 | Porteurs en propre             | Une personne peut porter plusieurs membres sans pouvoir (elle-même, une société dont elle est représentante légale, une indivision) ; ce n'est pas un mandat et les plafonds ne s'appliquent pas. Un membre n'a qu'un seul porteur.                                                                                                                                          |
| 2026-10-01 | Pouvoirs en blanc              | Attribués au président de séance (en attente tant qu'il n'est pas désigné, réattribués s'il change) et non soumis aux plafonds. À valider juridiquement.                                                                                                                                                                                                                     |
| 2026-10-01 | Retour d'un partant            | Ses voix propres lui reviennent toujours (le mandant présent reprend ses voix). Les pouvoirs qu'il détenait lui reviennent s'il était parti « temporairement » ou s'ils n'avaient pas été transmis ; transmis lors d'un départ définitif, ils restent au nouveau mandataire.                                                                                                 |
| 2026-10-01 | Émargement avant l'ouverture   | L'émargement et les mouvements sont possibles dès que l'AG est convoquée (le quorum se constate avant l'ouverture de la séance). Le retour en brouillon est impossible une fois l'émargement commencé.                                                                                                                                                                       |
| 2026-10-02 | Codes de vote                  | 16 caractères Crockford base32 (80 bits) ; seule l'empreinte SHA-256 est stockée. Le code circule dans le fragment d'URL (`/v#CODE`), jamais envoyé au serveur ni journalisé. Un code par personne, un appareil par personne et par AG ; un code déjà associé est refusé sur un autre appareil. Validité : jour de séance + 36 h ; plus aucune validité une fois l'AG close. |
| 2026-10-02 | Sessions anonymes (production) | À activer dans le projet Supabase de production (Authentication → Sign In / Providers → Anonymous). La limite par défaut (30 connexions anonymes par heure et par IP) doit être relevée : en salle, tous les votants peuvent partager la même IP publique. À reporter dans le RUNBOOK du jour J.                                                                             |
